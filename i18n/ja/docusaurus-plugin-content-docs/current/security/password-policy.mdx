# パスワードポリシー

Logto では、パスワードの作成や更新方法によってパスワードポリシーの適用方法が異なります：

- [標準のサインイン体験](/end-user-flows/sign-up-and-sign-in/sign-up)、[体験 API](/customization/bring-your-ui)、[アカウント API](/end-user-flows/account-settings/by-account-api#update-users-password) などのエンドユーザーフローでは、常に現在の [パスワードポリシー](#set-up-password-policy) が強制されます。
- 管理者による Management API [`patch /api/users/{userId}/password`](https://openapi.logto.io/operation/operation-updateuserpassword) 経由の操作は例外であり、必要に応じてポリシーチェックなしで資格情報のプロビジョニングやリセットが可能です。
- 既存のパスワードが現在のルールに準拠しているか監査するには、[`POST /api/sign-in-exp/default/check-password`](https://openapi.logto.io/operation/operation-checkpasswordwithdefaultsigninexperience) を呼び出し、返されたバリデーション結果に基づいて対応します。詳細は [パスワード準拠チェック](#password-compliance-check) を参照してください。

## パスワードポリシーの設定 \{#set-up-password-policy}

新規ユーザーやパスワードを更新するユーザーに対して、パスワードの強度要件を強制するパスワードポリシーを設定できます。<CloudLink to="/security/password-policy">コンソール > セキュリティ > パスワードポリシー</CloudLink> でパスワードポリシーの設定を行ってください。

1. **最小パスワード長**：パスワードに必要な最小文字数を設定します。（NIST は少なくとも 8 [文字](https://pages.nist.gov/800-63-3/sp800-63b.html#sec5) を推奨）
2. **必要な文字種の最小数**：パスワードに必要な文字種の最小数を設定します。利用可能な文字種は以下の通りです：
   1. 大文字：`(A-Z)`
   2. 小文字：`(a-z)`
   3. 数字：`(0-9)`
   4. 記号：``(!"#$%&'()\*+,-./:;<>=?@[]^\_`|{}~ )``
3. **漏洩履歴チェック**：この設定を有効にすると、過去にデータ漏洩で公開されたパスワードを拒否します。（[Have I Been Pwned](https://haveibeenpwned.com/Passwords) により提供）
4. **繰り返しチェック**：この設定を有効にすると、同じ文字が繰り返されるパスワードを拒否します。（例：「11111111」や「password123」など）
5. **ユーザー情報チェック**：この設定を有効にすると、ユーザー名、メールアドレス、電話番号などのユーザー情報を含むパスワードを拒否します。
6. **カスタムワード**：パスワードに含めたくないカスタムワード（大文字・小文字を区別しない）をリストで指定できます。

## パスワード有効期限 \{#password-expiration}

パスワード有効期限を設定すると、一定日数ごとにユーザーにパスワードのリセットを求めることができます。また、特定のユーザーのパスワードを手動で失効させることも可能です（例えば漏洩が判明した場合など）。

このポリシーは、ユーザーがパスワードサインイン時に正しいパスワードを入力した後のみチェックされます。認証コード、ソーシャルサインイン、SSO、パスキーでサインインするユーザーには影響しません。

### パスワード有効期限の有効化 \{#enable-password-expiration}

<CloudLink to="/security/password-policy">コンソール > セキュリティ > パスワードポリシー</CloudLink> で
**パスワード有効期限** カードを見つけてください：

1. **パスワード有効期限を有効にする** をオンにします。
2. **パスワード有効期間（日数）** を 1 ～ 9999 日の間で設定します。
3. 変更を保存します。

このトグルは、サインイン体験に少なくとも 1 つの [パスワード再設定](/end-user-flows/sign-up-and-sign-in/reset-password#forgot-password-for-account-recovery) 方法（メールまたは電話）が有効なコネクターで設定されている場合のみ有効になります。ユーザーはこのフローを通じてのみ期限切れパスワードをリセットできるためです。同じ理由で、ポリシー有効時はパスワード再設定をサポートする最後のメールまたは SMS コネクターを削除できません。サインアップ時にメールアドレスや電話番号が必須でない場合、一部のユーザーはリセットコードを受け取れない可能性があるため、サインアップ時に収集することを検討してください。

Logto は、ユーザーのパスワードが最後に設定または変更された日時を記録します。そのパスワードが有効期間と同じだけ古くなると、次回のパスワードサインイン時にリセットを求められます。パスワード変更日時が記録されていないユーザーは、ポリシー有効化時点から計測されるため、有効化しても全員のパスワードが一度に期限切れになることはありません。ポリシーをオフにして再度オンにすると、この開始時刻がリセットされます。

ユーザーが新しいパスワードを設定するとき（パスワード再設定、[アカウント API](/end-user-flows/account-settings/by-account-api#update-users-password)、または Management API 経由）、パスワードの有効期間はリセットされ、手動での失効もクリアされます。

### ユーザーのパスワードを手動で失効させる \{#expire-a-users-password-manually}

パスワード有効期限ポリシーが有効な場合、特定のユーザーに次回サインイン時にパスワードリセットを強制できます：

- **コンソール**：<CloudLink to="/users">コンソール > ユーザー管理</CloudLink> でユーザー詳細ページを開き、パスワード横の **失効** ボタンをクリックし、操作を確認します。ユーザーがパスワードを持っている場合のみボタンが表示されます。
- **Management API**：次のボディで [`PATCH /api/users/{userId}/password/expiration`](https://openapi.logto.io/operation/operation-updateuserpasswordexpiration) を呼び出します：

  ```json
  {
    "isExpired": true
  }
  ```

ポリシーが有効でない場合、API は `400` とエラーコード `sign_in_experiences.password_expiration_not_enabled` を返し、コンソールの **失効** ボタンも無効になります。

よくあるケースは、パスワードが漏洩していることが判明した場合です。失効させることで、ユーザーは新しいパスワードを設定して再度サインインする前に、認証コードでメールアドレスまたは電話番号の所有を証明する必要があります。すべてのユーザーに定期的なローテーションを強制せず、手動でのみ失効させたい場合は、有効期間を 3650 日など長めに設定してポリシーを有効にしてください。

パスワードを失効させても、既存のセッションからユーザーをサインアウトさせることはありません。即時にアクセスを遮断したい場合は、[ユーザーのアクティブセッション](/user-management/manage-users#manage-user-active-sessions) や [認可済みサードパーティアプリ](/user-management/manage-users#manage-user-authorized-third-party-apps) も取り消してください。

### エンドユーザーの画面イメージ \{#what-end-users-see}

ユーザーが期限切れパスワードでサインインすると、正しいパスワード入力後に「パスワードの有効期限が切れました。サインインする前にリセットしてください。」というメッセージ付きのモーダルが表示されます。**パスワードをリセット** をクリックすると、識別子が自動入力された状態でパスワード再設定フローに遷移します。メールまたは電話に送信されたコードで認証し新しいパスワードを設定すれば、再度サインインできます。

[体験 API](/customization/bring-your-ui) で独自のサインイン UI を構築している場合、パスワード検証リクエストはエラーコード `password.expired`（HTTP 422）で失敗します。このエラーを検知し、ユーザーをパスワードリセットフローに誘導してください。

## パスワード準拠チェック \{#password-compliance-check}

Logto でパスワードポリシーを更新した後も、既存ユーザーは現在のパスワードでサインインできます。新規作成アカウントのみが更新後のポリシーに従う必要があります。

より強固なセキュリティを実現するため、`POST /api/sign-in-exp/default/check-password` [API](https://openapi.logto.io/operation/operation-checkpasswordwithdefaultsigninexperience) を利用して、ユーザーのパスワードがデフォルトサインイン体験で定義された現在のポリシーに準拠しているか確認できます。準拠していない場合は、[アカウント API](/end-user-flows/account-settings/by-account-api) を使ったカスタムフローでパスワード更新を促してください。
